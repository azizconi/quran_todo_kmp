# Quran Hifz — Android redesign

Статус (2026-10-28): фазы 0–3 реализованы в ветке `redesign/android` и приняты на эмуляторе (API 35): дизайн-система, каркас, главный, ридер с плеером и режимом заучивания, «Прогресс», настройки, онбординг, общие переходы, круговое раскрытие темы, предиктивный «назад». Не сделано: фаза 4 (фоновое воспроизведение, «Мусхаф», джузы, проверка чтения микрофоном, чистка мёртвого кода), ссылка на политику конфиденциальности в настройках (нужен URL).
Область: только Android. iOS продолжает работать на текущем общем UI (`App()` → `HifzAppShell`) и нативном SwiftUI; новый UI живёт в `androidMain` и не трогает iOS.

Этот документ — единственный источник правды для всех агентов-исполнителей. Если в задаче что-то противоречит документу, прав документ; если документ молчит, исполнитель выбирает самое простое решение в духе раздела 1 и пишет об этом в отчёте.

## 0. Что есть сейчас (итог изучения)

Живой Android-путь сегодня:

```
MainActivity (androidx NavHost: "library" | "settings" | "surah/{n}")
 ├─ "library"   → App() → HifzAppShell → QuranLibraryRoute      (commonMain)
 ├─ "surah/{n}" → App() → HifzAppShell → SurahScreen + ReaderPlayerSheet (commonMain)
 └─ "settings"  → NativeSettingsScreen                          (androidMain, Material3)
Онбординг (внутри App): язык → шрифт. GoalsOnboarding никогда не показывается.
```

Проблемы, которые редизайн обязан закрыть:

1. **Двойная навигация.** Каждый маршрут NavHost создаёт новый `App()` с собственным Decompose-стеком, онбординг-гейтом и CompositionLocal-ами. Общие элементы (shared transitions) между экранами в такой схеме невозможны, переходы — системный кроссфейд.
2. **Смешение Material 2 и Material 3.** Тема — M2 (`androidx.compose.material`), кусками M3, у настроек своя M3-схема. Нет единой дизайн-системы, нет motion-токенов, нет тактильного отклика.
3. **Библиотека перегружена статусами.** У каждой из 114 строк крупная плашка «Не начал ▾» спорит с названием суры.
4. **Плеер принадлежит экрану чтения.** Выход из суры обрывает звук; продолжить слушать с главного нельзя.
5. **Заучивание спрятано.** В данных есть статус по аятам, SM-2 повторения (`AyahReviewEntity`, `ReviewStateStore`, `Sm2Scheduler`), слабые аяты, заметки к аятам, статистика (`StatsViewModel`), распознавание чтения — но в живом UI есть только статус суры. Логика «Сегодня» (`buildTodayTasks`) и сессия заучивания (`HifzSessionScreen`) лежат мёртвым кодом.
6. **Поиск обещает «по аяту», но не умеет.** Запрос `2:255` ничего не находит.
7. Позиция чтения и позиция аудио пишутся в один ключ и перетирают друг друга.
8. Bismillah: в `quran-uthmani` (api.alquran.cloud) первый аят сур 2–114 (кроме 9) начинается с «بِسْمِ ٱللَّهِ ٱلرَّحْمَٰنِ ٱلرَّحِيمِ». Сейчас это никак не оформлено.

Мёртвый код в commonMain (не используется ни Android, ни iOS): `presentation/home/HomeScreen.kt`, `presentation/stats/StatsScreen.kt`, `presentation/settings/SettingsScreen.kt`, `presentation/hifz/HifzHomeScreens.kt`, `presentation/hifz/HifzSessionScreen.kt`, `presentation/onboarding/{FeatureGuide*,CardStyle*,Goals*}`, `navigation/AppNavHost*`. **Не удалять в рамках редизайна** (затрагивает iOS) — можно и нужно копировать из них логику.

## 1. Принципы

1. **Текст Корана — главный герой.** Всё остальное тише: хром отступает, когда человек читает; украшения — тонкие золотые линии, а не баннеры.
2. **Одно главное действие на экране.** Главный: «Продолжить». Чтение: читать/слушать. Заучивание: вспомнить → проверить → оценить.
3. **Каждое касание отвечает.** Нажатие — пружинное сжатие + тактильный тик. Смена состояния — морфинг, а не мгновенная подмена. Важное достижение — маленький праздник (частицы + `CONFIRM`-вибрация), но не чаще, чем оно реально случается.
4. **Движение объясняет пространство.** Экран не «появляется», он вырастает из того, что нажали (shared bounds). Назад — возвращается в исходную точку. Предиктивный жест «назад» показывает, куда вернёмся.
5. **Никакой геймификации ради геймификации.** Нет бейджей, очков, лент. Прогресс — честные цифры и карта Корана на отдельном экране.
6. **Уважать человека.** Reduce Motion, крупный шрифт (до 1.3×), TalkBack, тёмная тема, оффлайн — не «потом», а критерии приёмки каждого экрана.

## 2. Визуальный язык: «Мусхаф»

Тёплая бумага днём, чернильная ночь. Изумруд — бренд и «выучено». Золото — орнамент и «заучиваю». Терракота — «пора повторить». Геометрия восьмиконечной звезды (Руб аль-Хизб ۞) — единственный орнаментальный мотив, рисуется кодом (Canvas), без растровых картинок.

### 2.3 Форма, отступы, глубина

- Скругления: `xs 8`, `sm 12`, `md 16`, `lg 22`, `xl 28` (верх листов), `full` (пилюли). Кнопки — пилюли. Карточки — `lg`. Плеер-док — `xl` сверху.
- Сетка 4dp. Боковой отступ экрана — **20dp**. Между секциями — 28dp. Внутри карточек — 16–20dp.
- Глубина — тональная. Тени только у двух вещей: герой-карточка и плавающий мини-плеер: мягкая цветная тень (`primary` @ 18%, blur ~24dp, offset y 8dp). Остальное — плоско с hairline-обводкой.
- Иконки: `Icons.Rounded.*` (material-icons-extended), 22dp в тулбарах, 20dp в кнопках.
- Минимальная область касания — 48dp, даже если визуально элемент меньше.

### 2.4 Орнамент (Canvas, `ui/components/Ornaments.kt`)

- `EightPointStar` — две квадратные рамки, повёрнутые на 45°. Параметры: размер, толщина линии, заливка, цвет. Основа номер-бейджа суры.
- `SurahNumberBadge(number, status, progress)` — звезда 40dp с номером внутри (табличные цифры). `null` статус: hairline-контур. `LEARNING`: золотой контур + дуга прогресса по окружности (выученные аяты / все). `LEARNED`: залитая изумрудом звезда, номер `onPrimary`. Статус передаётся формой и заливкой, а не только цветом.
- `StarLattice` — повторяющийся узор из восьмиконечных звёзд линиями 1dp, альфа 5–8%. Фон героя и шапки ридера; может слегка смещаться при скролле (параллакс 0.2).
- `OrnamentDivider` — hairline — маленькая звезда — hairline, золото @ 60%.
- `SurahCartouche` — рамка шапки ридера: скруглённый прямоугольник с двойной золотой линией и звёздами по бокам.
- `AyahRosette(number)` — розетка 34dp (круг с 8 «лепестками») с номером аята; кольцо статуса аята: золото — заучиваю, изумруд — выучено, точка терракоты — слабый.

## 3. Motion-система (`ui/motion/`)

### 3.1 Токены

```kotlin
object QhMotion {
    // длительности, мс
    const val Instant = 90; const val Short = 160; const val Medium = 280; const val Long = 420; const val Hero = 520
    // кривые
    val Emphasized = CubicBezierEasing(0.2f, 0f, 0f, 1f)
    val EmphasizedDecelerate = CubicBezierEasing(0.05f, 0.7f, 0.1f, 1f)
    val EmphasizedAccelerate = CubicBezierEasing(0.3f, 0f, 0.8f, 0.15f)
    // пружины
    fun <T> snappy()   = spring<T>(dampingRatio = 0.82f, stiffness = 420f)   // состояния UI
    fun <T> bouncy()   = spring<T>(dampingRatio = 0.55f, stiffness = 380f)   // чек, «поп» бейджа
    fun <T> gentle()   = spring<T>(dampingRatio = 1f,    stiffness = 220f)   // размеры, контент
    fun <T> press()    = spring<T>(dampingRatio = 0.7f,  stiffness = 900f)   // сжатие при нажатии
    fun <T> bounds()   = spring<T>(dampingRatio = 0.86f, stiffness = 320f)   // shared bounds
}
```

### 3.2 Reduce Motion

`LocalReducedMotion: Boolean` = системный `Settings.Global.ANIMATOR_DURATION_SCALE == 0f` ИЛИ пользовательский тумблер «Меньше анимаций». При `true`: переходы экранов — только кроссфейд 150мс, shared elements отключены, частицы/параллакс/стаггер выключены, пружины → `snap()`. Все хелперы ниже обязаны это уважать сами, чтобы экраны не думали об этом.

### 3.3 Хелперы

- `Modifier.pressable(onClick, onLongClick?, haptic = Tick, scale = 0.97f)` — пружинное сжатие (`press()` вниз, `snappy()` вверх), без серого ripple (вместо него лёгкое затемнение `surfaceStrong` @ 40%), тактильный тик на клик, `LONG_PRESS` на долгое нажатие, корректная семантика `Role.Button`. **Все** кликабельные элементы нового UI используют его.
- `Modifier.sharedElementKey(key)` / `Modifier.sharedBoundsKey(key, resize = …)` — no-op, если нет `LocalSharedTransitionScope`/`LocalNavAnimatedVisibilityScope` или включён Reduce Motion. Ключи — только из `SharedKeys` (3.5).
- `Modifier.staggeredEnter(index, enabled)` — fadeIn 300 + slideUp 16dp, задержка `index × 30мс`, максимум 8 элементов; срабатывает один раз за жизнь процесса для данного экрана (не при каждом возврате назад).
- `AnimatedCounter(value, style)` — цифры прокатываются вверх/вниз по одной (`AnimatedContent` на каждый разряд, 220мс).
- `AnimatedProgressBar` / `ProgressRing(progress)` — анимируют значение `gentle()`, при первом показе растут от 0.
- `CelebrationBurst(trigger)` — 14 частиц (золото + изумруд), радиальный разлёт 700мс, затухание; вызывается при «Выучено» и в конце сессии заучивания.
- `CircularRevealThemeSwitch` — смена темы с круговым раскрытием из точки касания (см. 6.6).

### 3.4 Переходы между экранами (NavHost)

- Вперёд: вход `fadeIn(220, delay 60) + slideInHorizontally(+6% ширины, 380мс, EmphasizedDecelerate)`; выход `fadeOut(160) + scaleOut(0.96, 380мс)`.
- Назад: зеркально (вход `scaleIn(0.96)+fadeIn`, выход `slideOut(+6%)+fadeOut`).
- Предиктивный «назад» (Android 14+): `android:enableOnBackInvokedCallback="true"` в манифесте; NavHost сам проигрывает pop-переход по жесту.
- Shared elements поверх этих переходов (раздел 7).

### 3.5 Ключи общих элементов (`ui/motion/SharedKeys.kt`)

`origin` — откуда открыли («hero», «list», «recent», «today», «search», «map», «player»). Он передаётся в маршрут, чтобы одна и та же сура в герое и в списке не конфликтовала.

```kotlin

    fun surahBadge(origin: String, n: Int)     = "surah-badge-$origin-$n"
    const val PlayerDock = "player-dock"
    const val PlayButton = "player-play"
    const val ProgressRing = "progress-ring"
    const val SettingsIcon = "settings-icon"

```

### 3.6 Тактильный отклик (`ui/haptics/Haptics.kt`)

`LocalHaptics.current.perform(HapticKind)`; выключается тумблером в настройках.

| Kind | Константа (fallback) | Когда |
|---|---|---|
| `Tick` | `CONTEXT_CLICK` | любое нажатие кнопки/карточки |
| `Segment` | `SEGMENT_TICK` (API 34) → `CLOCK_TICK` | сегменты, чипы, переключатели |
| `Step` | `SEGMENT_FREQUENT_TICK` (API 34) → `CLOCK_TICK` | шаги слайдера, колесо аятов |
| `LongPress` | `LONG_PRESS` | долгое нажатие |
| `Success` | `CONFIRM` (API 30) → `LONG_PRESS` | «Выучено», конец сессии |
| `Reject` | `REJECT` (API 30) → `LONG_PRESS` | ошибка, «Забыл» |

### 4.2 Состояние и данные

- Общие ViewModel-и (`HomeViewModel`, `SurahViewModel`, `StatsViewModel`) — синглтоны Koin, **не менять их публичное поведение** (их использует iOS). Можно добавлять новые публичные методы, если без этого никак.
- Для каждого экрана — свой Android-ViewModel в `ui/<feature>/`, который собирает UI-состояние из общих VM, DAO и `UiPrefs`. Регистрируется в своём Koin-модуле в `ui/di/UiModules.kt` (фаза 0 создаёт пустые модули и подключает их в `startKoin`).
- Логику «Сегодня» перенести из мёртвого `HifzHomeScreens.buildTodayTasks` в `ui/home/TodayPlanner.kt` (чистая функция + unit-тест в `androidUnitTest` или `commonTest`-подобном месте).
- Корневое состояние приложения (язык, тема, палитра, шрифт, размер шрифта, AppSettings) — в `QuranHifzApp`, отдаётся существующими `Local*`-провайдерами из commonMain (`LocalAppLanguage`, `LocalAppStrings`, `LocalThemeMode`, `LocalReadingFontStyle`, `LocalAppSettings` …), чтобы переиспользуемые общие функции (`getQuranFontFamily()` и т. п.) продолжали работать. Побочные эффекты из `App()` повторить: телеметрия `app_opened`/экраны, отключение напоминаний (`ReminderScheduler.syncDailyReminder(false)`), реакция на `SettingsChangeNotifier`.

### 4.3 UiPrefs (новые Android-настройки, SharedPreferences)

`themeFollowsSystem: Boolean` (по умолчанию true, если тема ещё не сохранена), `hapticsEnabled = true`, `reduceMotion = false`, `readerLayout = LIST`, `keepScreenOn = true`, `recentSurahs: List<Int>` (до 8, последняя первой), `pinnedSurahs: Set<Int>`, `lastReadSurah`/`lastReadAyahInSurah` (позиция чтения, отдельно от аудио; если пусто — fallback на старый `getLastPlaybackSurah/AyahNumber`), `onboardingGoals: Set<String>` (`read`/`listen`/`memorize`), `hifzHintMode` (нет/первое слово). Наблюдаемые через `StateFlow`.

`ThemeMode` (общий enum) **не расширять** — режим «Как в системе» хранится в `UiPrefs.themeFollowsSystem`.

### 4.4 PlaybackController (звук живёт выше экранов)

Синглтон в `ui/playback/`, создаётся в Koin с app-scope `CoroutineScope(SupervisorJob() + Dispatchers.Main.immediate)`, внутри — один `ReaderAudioSession`.

```kotlin
data class NowPlaying(val surahNumber: Int, val ayahs: List<ReaderAudioAyah>)
class PlaybackController {
    val nowPlaying: StateFlow<NowPlaying?>
    val state: StateFlow<ReaderAudioState>           // проксирует session.state
    fun isActiveFor(surah: Int): Boolean
    fun start(surah: SurahWithAyahs, prefs: SurahReaderPreferences, practice: ReaderPracticeSettings, fromIndex: Int, autoplay: Boolean = true)
    fun toggle(); fun next(); fun previous(); fun select(index: Int)
    fun updateSettings(prefs: SurahReaderPreferences, practice: ReaderPracticeSettings)

```

Правила: открытие суры Y во время игры суры X **не перехватывает** звук — ридер Y показывает свой плеер в состоянии «готов», а сверху маленький чип «Играет: X». Нажатие play в ридере Y вызывает `start(Y, …)`. Выход из ридера звук не останавливает; на главном появляется мини-плеер. Фоновое воспроизведение с выключенным экраном (Media3 + уведомление) — отдельная фаза 4.

### 6.2 Онбординг (первый запуск)

Слушайте. Заучивайте.» Ниже — 5 карточек языков с родным названием и монограммой (Ру, En, Тҷ, Uz, Tr). Выбор языка мгновенно перерисовывает тексты экрана кроссфейдом.

Старые отдельные листы «Повтор» и «Пауза» с гайдом-иллюстрацией заменяются этими секциями; гайд показывается один раз как подсказка-тост с картинкой `player_guide_art`.

**Лист «Aa».** Превью аята, слайдер размера 22–40 (`Step`), карусель шрифтов, «Перевод» (свитч), «Макет: Список / Мусхаф» (Мусхаф — фаза 4, до неё пункт скрыт), быстрый переключатель темы, «Не гасить экран».

**Конец суры.** Карточка «Следующая сура: …» → `onOpenReader` с переходом shared-axis X. Последняя сура — «Вы дочитали Коран до конца» с орнаментом.

`keepScreenOn` по умолчанию во время чтения и всегда во время игры (`View.keepScreenOn`).

### 6.5 Режим заучивания (внутри ридера)

Включается «👁» в шапке или открытием задачи «Сегодня». Шапка меняет цвет на `goldContainer`, сверху полоса прогресса сессии «4 / 10».

- Текст аятов скрыт: на Android 12+ `Modifier.blur(14.dp)` + альфа 0.35; ниже 12 — вместо текста «строки-заглушки» (скруглённые полосы `surfaceStrong` по ширине строк). Опционально видно первое слово (`UiPrefs.hifzHintMode`).
- Удержание аята — «подсмотреть» (размытие уходит, пока палец на аяте, пружина `snappy()`).
- Кнопка «Показать» под текущим аятом → размытие 14→0 за 320мс; под ним выезжает ряд оценок: «Забыл» (`Reject`) · «Трудно» · «Хорошо» · «Легко». Оценка → `SurahViewModel.completeReview(ayah, surah, quality)`; для новых аятов также `updateAyahStatus(LEARNING)`. Текущий аят сворачивается, список доезжает к следующему.
- «🎧» у скрытого аята — проиграть его (послушать → вспомнить).
- Конец сессии: лист-итог с `ProgressRing`, разбивкой «Легко / Хорошо / Трудно / Забыл», `CelebrationBurst` + `Success`. Действия: «Повторить трудные» (новая сессия из HARD+FORGOT), «Готово».
- Выход из режима — «👁» ещё раз или «назад»; прогресс сессии не теряется при повороте экрана (`rememberSaveable`).

### 6.6 Настройки

Крупный заголовок, группы-карточки, у пунктов цветные иконки-плитки.

1. **Внешний вид:** сегменты «Светлая · Тёмная · Системная» (иконки солнце/луна морфят); палитры — три круга, выбранный с кольцом и галочкой (`bouncy()`); «Арабский шрифт» → лист типографики (превью + карусель + размер); «Макет чтения» (фаза 4).
2. **Чтение:** перевод (свитч), подсветка играющего аята, не гасить экран.
3. **Звук:** автозапуск при открытии, автопереход к следующему аяту, скорость (чипы прямо в строке), повтор аята (чипы), чтец — информационная строка «Мишари Аль-Афаси».
4. **Заучивание:** аятов в день (шаговый счётчик), подсказка первого слова.
5. **Язык:** лист с 5 языками; смена — кроссфейд всего UI.
6. **Данные:** «Скачать для оффлайн» с встроенным прогрессом (`QhLinearProgress` + счётчик), «Резервная копия», «Восстановить» (диалог подтверждения, деструктивная кнопка), статус синхронизации.
7. **Удобство:** тактильный отклик, «Меньше анимаций».
8. **О приложении:** версия, политика конфиденциальности (ссылка из store listing), «Оценить».

**Круговое раскрытие темы:** перед сменой снять кадр текущего UI (`rememberGraphicsLayer` → `toImageBitmap()`), применить новую тему, поверх нарисовать старый кадр с вырезанным расширяющимся кругом из точки касания (520мс, `Emphasized`). Системные бары меняют цвет синхронно. При Reduce Motion — кроссфейд 150мс.

### 6.7 Прогресс (новый, можно отключить одним решением)

Открывается кольцом в шапке главного (shared element `ProgressRing`).

- Крупное кольцо: выученные аяты / 6236, процент считается вверх (`AnimatedCounter`), под ним «412 аятов · 3 суры выучено · 5 в процессе».
- **Карта Корана:** сетка 114 ячеек (по 10 в ряд), цвет — статус суры; выученные при появлении проходят «волной» золотого блика с задержкой по индексу. Нажатие на ячейку → тултип с названием и «Открыть» (ридер, `origin = "map"`).
- Плитки: «Дней подряд», «Повторить сегодня», «Слабых аятов», «Аятов в работе» — `AnimatedCounter`.
- Активность за 14 дней (`StatsViewModel.last14DailyCounts`): столбики растут при появлении, нажатие — значение.
- «Слабые места по сурам» → кнопка «Повторить» открывает ридер в режиме заучивания на слабых аятах.

Данные — `StatsViewModel` + `HomeViewModel`.

## 8. Критерии приёмки (для каждого экрана)

1. `./gradlew :composeApp:assembleDebug` и `./gradlew :composeApp:testDebugUnitTest` проходят.
2. Светлая и тёмная темы во всех трёх палитрах; нет «чужих» серых полос у системных баров.
3. Шрифт системы 1.3× — ничего не обрезано, ничего не налезает.
4. TalkBack: у иконок есть подписи на языке приложения, статусы озвучиваются (`stateDescription`).
5. Reduce Motion (масштаб анимаций 0 в параметрах разработчика) — экран работает, без shared/частиц.
6. Нет лишних рекомпозиций: прогресс аудио не рекомпозирует весь список (читать состояние в листовых composable).
7. Все 5 языков заполнены; RU и EN вычитаны; TG/UZ/TR — используя глоссарий (раздел 10).
8. Каждый кликабельный элемент — `pressable` или компонент дизайн-системы (с вибрацией).
9. Не трогать файлы вне своей зоны (раздел 9). Если не хватает компонента — локальная обёртка в своей папке и пункт в отчёте.
