# Quran Hifz — план упрощения (после 2.0.0)

Дата: 2026-11-10. Ветка: `redesign/android`. Платформа: Android.

## Зачем

Обещание приложения — «Заучивайте Коран каждый день — понемногу и без забывания» (`PRODUCT_PLAN.md`, раздел 1). В 2.0 вокруг урока дня выросло много соседних фич: несколько тренировок, второй план (хатм), аналитика, 34 строки настроек, онбординг из 9 шагов, 6 туров подсказок. Человек тратит силы на то, чтобы разобраться, вместо того чтобы учить.

Цель — чтобы новый человек за первую минуту понял одно: **открой урок дня и пройди его**.

## Принципы

1. **Данные не трогаем.** Таблицы Room, файл резервной копии и его формат остаются как есть: никаких миграций, старые копии восстанавливаются. Убираем только точки входа и экраны.
2. **Сначала прячем, потом удаляем.** Каждая убираемая фича выключается флагом в одном объекте `ui/Features.kt` (`const val`, R8 вырежет мёртвый код). Код удаляем отдельным PR через один выпуск, если никто не попросил вернуть.
3. **Контекстные входы оставляем.** Фича, которая появляется ровно там, где нужна (похожие аяты из листа аята, тренировка из «Трудных мест»), не мешает. Убираем входы, которые висят «на всякий случай».
4. **Решения по данным.** Все новые экраны 2.0 уже пишут `logScreen` (`QuranHifzApp.kt`, `screenName()`). Данных пока нет: 2.0 ещё не вышла. Поэтому делим на две волны.

### Порядок и исполнители волны 1

S1–S4 не пересекаются по файлам, кроме `QuranHifzApp.kt` (S1, S2) и `SettingsScreen.kt` (S1, S3). Порядок: **S2 и S4 параллельно → S1 → S3**. По одному агенту на задачу в своём worktree, Opus ревьюит и мержит в `redesign/android`.

Проверка каждой задачи: `./gradlew :composeApp:testDebugUnitTest :composeApp:assembleDebug`, плюс скриншоты затронутых экранов на 2 языках (ru, en) для PR.

## Волна 2 — через 3–4 недели после выпуска (по данным Firebase)

Что смотреть в Firebase (экраны и события уже пишутся):

| Фича | Событие / экран | Порог «оставить» |
|---|---|---|
| Тест | `screen_view: quiz`, `check_completed` | ≥ 15% активных за неделю |
| Тренировка | `hard_drill`, `drill_completed` | ≥ 10% |
| Различи похожие | `tell_apart` | ≥ 5% |
| Подробная аналитика | `progress_details_opened` | ≥ 10% от открывших прогресс |
| Заметки | `notes_opened` | ≥ 5% |
| Тафсир | `tafsir` | ≥ 10% |
| Отчёт для устаза | `report_shared` | любое заметное число — оставить |

Не хватает событий (добавить в волне 1, это мелочь): поиск по переводу (`translation_search_used`), смена издания перевода (`translation_edition_changed`), прослушивание старого круга (`listen_old_started`), режим эха (`echo_started`).

### S5. Онбординг: 9 шагов → 5 (самое важное для новых пользователей)

Сейчас путь «Заучивать» (`OnboardingFlow.kt:59–78`): язык → история → цель → что знаю → пресет → темп → напоминание → комфорт → готово.

После: **язык → цель → что знаю → темп (пресет внутри) → готово.**

- «История» (несколько страниц) → убрать или оставить одну страницу. Смотреть `onboarding_story_skipped`: если пропускают больше половины — убрать.
- «Пресет» и «Темп» → один шаг: три карточки пресетов, под ними «настроить точнее».
- «Комфорт» (размер шрифта и т. п.) → значения по умолчанию, настройка остаётся в настройках.
- «Напоминание» → спросить после первого пройденного урока (лист на итогах урока). Разрешение на уведомления в момент, когда человек понимает зачем, дают чаще.

По `onboarding_step` смотреть, на каком шаге уходят люди, до и после.

### S6. Прогресс: один экран вместо трёх

- Экран «Подробнее» (`Dest.ProgressDetails`, аналитика за период) — спрятать, если ниже порога. Полезное (график активности) уже есть на главном экране прогресса.
- Список заметок — вход только из настроек (сейчас ещё и из прогресса и аналитики).
- Отчёт для устаза остаётся.

### S7. Чтение — по данным

- Поиск по переводу: убрать, если почти не используют.
- Выбор издания перевода: оставить (выбирают один раз).
- Тафсир и значения слов: оставить, если выше порога. Это контекстные входы из листа аята, они не мешают.

### S8. Удаление кода

Через один выпуск после того, как флаг выключен и никто не попросил вернуть: удалить экраны, view-модели, строки, тесты и маршруты. Таблицы Room и поля резервной копии **не удалять** (иначе нужна миграция и ломаются старые копии).
