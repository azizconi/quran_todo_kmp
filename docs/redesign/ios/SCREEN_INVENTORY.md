# iOS port: screen inventory and porting spec

Source of truth: Android Compose in `composeApp/src/androidMain/kotlin/tj/app/quran_todo/ui/` (paths below are relative to it).
Plan and stages: `docs/redesign/IOS_PORT_PLAN.md`. Written 2026-11-14 from a read of the code (not run). Items marked (verify) were
not read in full. Shared logic (VMs, `*Copy`, builders, `UiPrefs`) comes from `commonMain` via SKIE, so every "VM function" below is
called from Swift as is; this file only specifies the UI around them.

Legend: **Dest** = `navigation/Dest.kt` route. **State** = the field that drives a face. **Copy** = `ui/i18n/*Copy.kt` class.
"iOS" = suggested native idiom. Motion numbers are the Android ones (dp ~ pt, ms).

## 0. Global elements (S1 provides the pieces; every stage uses them)

### 0.1 Motion tokens (`motion/QhMotion.kt`) and SwiftUI equivalents
| Token | Android | SwiftUI |
|---|---|---|
| durations | Instant 90, Short 160, Medium 280, Long 420, Hero 520 ms | constants |
| Emphasized | cubic (0.2, 0, 0, 1) | `.timingCurve(0.2, 0, 0, 1, duration:)` |
| EmphasizedDecelerate (enter) | (0.05, 0.7, 0.1, 1) | `.timingCurve(0.05, 0.7, 0.1, 1, duration:)` |
| EmphasizedAccelerate (exit) | (0.3, 0, 0.8, 0.15) | `.timingCurve(0.3, 0, 0.8, 0.15, duration:)` |
| snappy (UI state) | spring damping .82, stiffness 420 | `.spring(response: 0.31, dampingFraction: 0.82)` |
| bouncy (check, badge pop) | .55 / 380 | `.spring(response: 0.32, dampingFraction: 0.55)` |
| gentle (sizes, content) | 1.0 / 220 | `.spring(response: 0.42, dampingFraction: 1.0)` |
| press (squeeze) | .7 / 900 | `.spring(response: 0.21, dampingFraction: 0.7)` |
| bounds (shared bounds) | .86 / 320 | `.spring(response: 0.35, dampingFraction: 0.86)` |
Response = 2*pi/sqrt(stiffness). Reduce Motion (`motion/ReducedMotion.kt`: system animator scale 0 OR in-app `UiPrefs.reduceMotion`)
turns every spring into `snap`, every slide into a 150 ms crossfade, stagger/celebration visuals off (haptics stay). iOS: read
`@Environment(\.accessibilityReduceMotion)` OR the in-app toggle; one `Motion.animation(_:)` wrapper.

### 0.2 Reusable motion behaviours (`motion/`)
- **pressable** (`Pressable.kt`): scale 0.97 on touch-down (press spring), back with snappy; pressed veil = `surfaceStrong` @ 0.4 alpha
  clipped to the shape (no ripple); haptic on tap, `LongPress` on long press; role/label for a11y. iOS: `ButtonStyle` with
  `scaleEffect` + overlay veil; hit-testing on unscaled bounds.
- **staggeredEnter** (`Stagger.kt`): first 8 items only, delay `index*30` ms, 300 ms decel, fade + translateY 16; plays once per screen
  (saveable flag set only when content is `ready`, so a skeleton does not use it up); not replayed on back/scroll. iOS: `.staggeredEnter(index)` modifier + `@State played` in the screen model.
- **AnimatedCounter** (`AnimatedCounter.kt`): digits roll up/down per place value, 220 ms Emphasized, aligned from the right. iOS: `Text(...).contentTransition(.numericText(value:))` + `.animation`. **rememberRollingValue** (`progress/ProgressMotion.kt`): counts 0 -> target in <= N eased strides (big first) so the digits roll like an odometer.
- **CelebrationBurst** (`Celebration.kt`): 14 gold/emerald particles (size 3.5-6.5, random angle jitter 0.35 rad, distance 0.6-1.0 of radius), 1100 ms linear clock, flight decelerates, opaque until 45% then smoothstep fade, plus a soft gold ring (0.5 alpha, 2dp, thins). Fires on `trigger` change, plays `Success` haptic. iOS: `Canvas` + `TimelineView`, or `PhaseAnimator`.
- **Shared elements** (`SharedElements.kt`, keys in `SharedKeys.kt`): `surahContainer/Title/Arabic/Badge(origin, surah)` (list row/hero/recent chip/search -> reader header), `PlayerDock` + `PlayButton` (mini player -> dock), `ProgressRing` (home top-bar ring -> progress big ring), `SettingsIcon` (gear -> settings header), `LessonCard` (home card -> lesson frame). Bounds spring = bounds(); container content fades in 280 ms after 100 ms delay, old content out in 110 ms; labels cross-fade 220 ms while scaling. `Origin` = hero/list/recent/today/search/map/player/next so duplicates never clash. **iOS 17 cannot do this across a NavigationStack push** (`matchedGeometryEffect` is single-hierarchy; `matchedTransitionSource` + `.navigationTransition(.zoom)` is iOS 18+). Recommendation: `#available(iOS 18)` zoom transition for surah row/hero/chip -> reader and lesson card -> lesson; iOS 17 = native push. Gear/ring flights: drop on iOS 17 (cross-fade title only).
- **Circular theme reveal** (`CircularReveal.kt`): snapshot old UI, new theme composes under it, old frame drawn with an expanding hole centred on the last touch; 520 ms Emphasized; reduced motion = 150 ms fade. iOS: overlay `UIView.snapshotView` + `CAShapeLayer` mask animation (host in `UIWindow` root); used by theme/palette changes in Settings.
- **Nav transitions** (`navigation/NavTransitions.kt`): push = new screen fades in (220 ms, 60 ms delay) and slides 6% of width in (380 ms decel), old scales to 0.96 + fades out 160 ms; pop mirrors (old shrinks to 0.92, slides 6% out, corners round to 28dp); reduced = 150 ms crossfade. iOS: keep native push + swipe-back (principle 3); do not recreate unless cheap.
- **Large collapsing top bar** (`components/TopBars.kt` `QhLargeTopBar`): display title (34/40, 800) collapses over 48dp of scroll to a compact title2; overline (greeting) fades out in the first 40%; hairline + bg@96% appear. iOS: `.navigationTitle` + `.navigationBarTitleDisplayMode(.large)` gives it free; use custom only where overline is needed (Lesson tab: greeting).
- **Skeleton** (`Skeleton.kt`): placeholder block, soft highlight sweep every 1150 ms linear; static under reduced motion. iOS: `.redacted(.placeholder)` + shimmer overlay.
- **QhSheet** (`Sheets.kt`): modal sheet, xl top corners 28, 32x4 hairline handle, `surface`, scrim token, content animates size (gentle). Always `skipPartiallyExpanded`. iOS: `.sheet` + `.presentationDetents([.medium, .large])` / `[.height]`, `.presentationDragIndicator(.visible)`, `.presentationCornerRadius(28)`. Pattern "hide with slide, then run action" (`rememberSheetCloser`) = set state in `onDismiss`/`DispatchQueue` after dismissal.
- **Dialogs**: `ConfirmDialog` (danger button on top, quiet Cancel under it) and Material `AlertDialog`. iOS: `.confirmationDialog` for the danger+cancel pattern, `.alert` for 2-button asks.
- **Wheel** (`Wheel.kt`) ayah picker: 5 rows, centre large, `Step` haptic per number. iOS: `Picker(.wheel)` is acceptable.
- **Calligraphy** (`Ornaments.kt` `CalligraphyText`): Amiri Quran text revealed right-to-left (soft edge sweep, `revealMillis`, optional single glint 0.9 s after), size in dp ignoring font scale, shrinks to fit width. Phrases: Bismillah (single ligature code point), Iqra, Alhamdulillah, "hifz". iOS: `Text` + `mask` with animated `LinearGradient` offset.

### 0.3 Haptics (`haptics/Haptics.kt`, gated by `UiPrefs.hapticsEnabled`)
| HapticKind | Used for | iOS |
|---|---|---|
| Tick | button/card press, tab change, sample play | `.sensoryFeedback(.selection)` or `UISelectionFeedbackGenerator` |
| Segment | segments, chips, switches, choice cards, grade pills | `.selection` |
| Step | steppers, ayah wheel, plan drag step | `.selection` (or `.impact(.light)`) |
| LongPress | long press, drag lift | `.impact(.medium)` |
| Success | memorized, session end, stop recording, "Check" done | `.success` |
| Reject | error, "Forgot", playback error | `.error` |
One `Haptics` service (S2) with the in-app toggle; never call generators directly.

### 0.4 Theme, palette, language, typography
- Root (`QuranHifzApp.kt`) owns: `language` (stored `LanguageStorage`, else device), `themeMode` (LIGHT/DARK; ignored while `UiPrefs.themeFollowsSystem`), `themePalette` FOREST/SAND/OCEAN (`ThemeStorage`), `readingFontStyle`, `ayahCardStyle`, `AppSettings` (dailyGoal, readingFontSize 22-40), `LocalReducedMotion`, `LocalHaptics`, `LocalToaster`, `LocalHints`. Settings changes go through root setters so the whole UI follows at once. iOS: one `@Observable AppEnvironment` injected with `.environment`; `preferredColorScheme(nil|.light|.dark)`.
- Tokens: `theme/QhColors.kt` (bg, surface, surfaceMuted, surfaceStrong, hairline, ink/inkSecondary/inkTertiary, primary/onPrimary/primaryContainer, gold/goldContainer, learned/learning/due (+containers), danger, readerBg/readerSurface/readerHighlight, scrim; light+dark per palette), `QhTypography` (display 34/40 w800, headline 26/32, title1 21/28, title2 17/24, body 16/24, callout 14/20, label 13/16, overline 11/14 tracked; quranBody 1.85 line, quranHeader 1.6, quranInline 1.4), `QhSpacing` (4-point; screen 20, section 28, card 16/20, minTouch 48), `QhShapes` (8/12/16/22/28/pill). Font: Manrope (UI), Tajik letters fall back (S1 must supply a Cyrillic-extended fallback). Arabic: reading fonts per `ReadingFontStyle` (7), Amiri Quran for calligraphy.
- App language is app-level (ru, tg, uz, en, tr), independent of the system: Swift reads Kotlin `*Copy` for the current `AppLanguage`. Language change crossfades text (`CrossfadeText`: 280 ms crossfade + gentle size animation). iOS: `.id(language)` + `.transition(.opacity)` on a container; `contentTransition(.opacity)` on Text.
- **Pronunciation of surah names**: one rule in `common/SurahNames.kt` (RU name for RU, transliteration otherwise); never invent names in Swift.

### 0.5 Toasts (`components/Toast.kt`)
`LocalToaster.show(message, ToastKind.Success|Error|Info, durationMillis)`; one at a time, a new message replaces the current; host at top-center of the root (`ToastHost`). Snackbar-style undo bars are separate (`UndoBar` in Notes, My reading). iOS: custom top banner overlay on the root (not system alerts); VoiceOver `AccessibilityNotification.Announcement`.

### 0.6 Inline hints (`components/hints/`)
`InlineHint(id, text)`: a quiet line inside the screen, no overlay/dimming; gone for good after the person does the thing once (`hints.markUsed(id)`) or taps x; `AnimatedVisibility` fade 160 + expand 280. Store: its own SharedPreferences file (`quran_hifz_spotlights`), NOT in `UiPrefs`, NOT in backup; "Show tips again" (Settings) = `hints.resetAll()`. iOS: `UserDefaults` suite, same ids. There are no spotlight/coach-mark overlays any more.

### 0.7 Persistent overlays at the root
| Overlay | Where | State | iOS |
|---|---|---|---|
| Toast host | root, top | `Toaster` | root overlay |
| Update-ready banner | root, bottom above tab bar (`LocalBottomChrome.height`) | `AppUpdates.readyToInstall` (Play flexible update) | no iOS equivalent; skip or lightweight "new version" banner via iTunes lookup (optional, default skip) |

## S3. Shell, navigation, onboarding, what's new, welcome back, home tabs

### S3.1 App entry and gate (`QuranHifzApp.kt`, `MainActivity.kt`, `onboarding/OnboardingGate.kt`, `OnboardingStartup.kt`)
- Start destination: `OnboardingGate.resolve()` -> `Passed` (Home), `ExistingUser` (language + font saved, v2 never started: mark passed, go Home, and the What's-new sheet becomes eligible), `Show` (Onboarding; also resumes an interrupted one). Pure rule `decide(completed, languageSaved, fontSaved, v2Started)`; iOS existing users = same keys through legacy import (`HifzStartup`).
- Android: splash kept up until the Quran is read from DB (max `SPLASH_MAX_MILLIS`); not needed when onboarding is next. iOS: `LaunchScreen` + hold the first frame until `HomeUiState.phase != Loading` or timeout (skeleton covers the rest).
- Telemetry: `AppTelemetry.logScreen(screenName)` per Dest (home tab name: `home`/`quran`/`progress`) - port as a `.task(id:)` on route change.
- Reminder deep link (`reminder/ReminderLink.kt`): notification tap -> `ReminderTarget.Lesson` or `.Reader(surah, ayah?)`; waits (max 3 s, poll 40 ms) until nav is idle, drops everything above Home, selects tab Lesson (for Lesson target), pushes `Dest.Lesson` / routed reader with `origin="reminder"`. A deep link in this launch suppresses What's-new until the next launch. Widget uses the same link with `source=widget`. iOS: `UNUserNotificationCenterDelegate.didReceive` + `onOpenURL` (widget) -> `AppRouter.open(target)`.
- `navigateOnce`: navigation accepted only when current entry is idle (swallows double taps). iOS: debounce in `AppRouter.push` (ignore while `isTransitioning`).

### S3.8 Quran tab (`home/QuranTab.kt`, `HomeUiViewModel`, `components/*`)
Large "Quran" title + gear (long press = debug catalog on Android). `LazyColumn` items in order (each with stagger; hero 0, recent 1, tabs 2, search header 3, rows from 4, +delay per row, only first 8 animate):

## 9. Star icons / star motifs found in Android code
**None.** Searched `androidMain`, `commonMain`, `iosMain` for `Icons.*Star*`, `Sparkle`, `AutoAwesome`, star/stars glyphs, polygon star paths: no hits. The code actively avoids them (comments: "mihrab, never a star", "no stars and no eight-sided figures" in `PageCanvas.kt`, report image/PDF, Ramadan card, onboarding). One hazard for iOS: the bundled Quran text contains U+06DE (rub el hizb), which renders as an eight-pointed star; `hideRubSign`/`splitBismillah` hide it in every display path (reader, lesson, sheets, quiz, tafsir, similar) and only copy/share keep it - Swift must call the same Kotlin helpers for every Arabic text it draws. The only "star" word in code is the Play review card description ("the stars and the review text") - Apple's review prompt is system UI, nothing to draw. SF Symbols to avoid: `star*`, `sparkle*`, `wand.and.stars`; also avoid `seal`/`rosette`-style 8-pointed symbols and `asterisk`.
