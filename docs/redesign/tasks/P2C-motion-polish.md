## Что найдено на приёмке (исправить)

1. **Строка суры → ридер и обратно.** На обратном переходе арабское имя внутри картуша на середине анимации раздувается до огромного размера, названия накладываются друг на друга (Al-Fatihah поверх «Открывающая Коран»). На прямом — в первом кадре вокруг строки рисуется контур картуша. Причина почти наверняка в том, что текст с `sharedBounds(…, Scale)` в ридере занимает всю ширину (`fillMaxWidth`), а в строке — по содержимому, и `ScaleToBounds` растягивает маленький текст на широкий бокс. Сделай нормальный container transform:
   - контейнер: строка (прямоугольник со скруглением 0/lg) ↔ картуш-блок шапки, `sharedBounds(surahContainer, Remeasure)`, фон контейнера плавно меняется, содержимое старого/нового экрана кроссфейдится внутри (`enter = fadeIn(delay)`, `exit = fadeOut(fast)`);
   - бейдж-звезда ↔ бейдж в шапке: `sharedElement`, звезда плавно растёт;
   - арабское имя и название — `sharedBounds(..., Scale)` **на тексте с размером по содержимому** (`wrapContentWidth`, без `fillMaxWidth`; центрирование делает родитель) и `ContentScale.Fit`/`Inside` (добавь параметр в `sharedBoundsKey`, если нужен), либо `sharedElement` с `animateFloatAsState` размера шрифта — выбери то, что на кадрах выглядит чисто;
   - текст статуса, мета-строка и аяты ридера — не общие, они появляются fade + slideUp 24dp после 120мс.
   Проверь на кадрах все источники: строка списка (`list`), hero (`hero`), недавние (`recent`), задача «Сегодня» (`today`), результат поиска (`search`), ячейка карты в «Прогрессе» (`map`), следующая сура (`next` — там переход shared-axis, без общих элементов).
2. **Шестерёнка главного → настройки.** На главном она круглая кнопка, в настройках — плитка (`QhIconTile`). Сделай так, чтобы на перелёте форма не «прыгала»: либо обе без фона, либо фон морфит (скругление и цвет анимируются через `sharedBounds` на контейнере + `sharedElement` на самой иконке). Поворот на 90° при нажатии сохранить.
3. **Мини-плеер ↔ док ридера** (`PlayerDock`, `PlayButton`, `origin = player`): пилюля плавно становится доком, кнопка play летит на своё место. Проверь и обратный путь (назад из ридера, открытого из мини-плеера).
4. **Кольцо прогресса главного ↔ большое кольцо «Прогресса»** (`ProgressRing`).
5. Повторные быстрые нажатия во время перехода не должны ломать анимацию (корень уже блокирует навигацию — проверь, что ничего не «застревает» в оверлее).

## Что добавить

6. **Круговое раскрытие темы** (6.6): `ui/motion/CircularReveal.kt` + подключение в корне. Перед сменой темы снять кадр текущего UI (`rememberGraphicsLayer()` на корневом `Box` + `layer.toImageBitmap()`), применить новую тему, поверх нарисовать старый кадр с вырезанным расширяющимся кругом из точки касания, 520мс, `QhMotion.Emphasized`; системные бары меняются синхронно. Точку касания экраны передают через новый `LocalThemeRevealOrigin` / функцию `rememberThemeSwitcher()` (сделай API простым: `switcher.switch(mode, origin: Offset)`). Подключи в настройках (сегменты темы, палитры) и в листе «Aa» ридера (кнопка темы). При Reduce Motion — кроссфейд 150мс.
7. **Предиктивный «назад»** (Android 14+): проверь, что pop-переход проигрывается по жесту (в манифесте флаг уже стоит). Если NavHost этой версии не даёт прогресса жеста — используй `PredictiveBackHandler` в корне, чтобы хотя бы уменьшать (scale 0.94) и скруглять уходящий экран по прогрессу жеста, а при отмене — возвращать. Проверь на эмуляторе свайпом от края (`adb shell input swipe 2 1200 600 1200 600`).
8. **Аудит** (по коду + кадрам):
   - каждый кликабельный элемент — `pressable` или компонент дизайн-системы, без двойной вибрации;
   - стаггер срабатывает один раз (не при каждом возврате на главный);
   - при `animator_duration_scale 0` (Reduce Motion системой) — никаких shared/частиц/параллакса, переходы — кроссфейд, ничего не ломается.
