# Задача F7 — прототип проверки чтения наизусть голосом

Исполнитель: Sonnet. Ветка: твой worktree от `redesign/android`. Работаешь один, эмулятор твой с момента, когда код готов.

## Цель

Это **прототип для решения «делаем / не делаем»**, а не фича для выпуска. Нужно ответить цифрами:

1. Находит ли модель на устройстве **пропуск и замену слова** в ≥ 90 % случаев при < 1 ложной ошибке на отрывок?
2. Укладывается ли разбор во время, не большее длины самого отрывка?
3. Сколько весит всё это (модель, нативная библиотека) и что нужно для выпуска.

Всё, что видит человек, — **только в debug-сборке**. В release ничего из F7 нет: ни нативной библиотеки, ни кнопок, ни строк в манифесте.

## Что сделать

### 1. Модель

- Скачай `tarteel-ai/whisper-base-ar-quran`, сконвертируй в ggml скриптом whisper.cpp, сделай квантизации `q8_0` и `q5_0` (и f16 для сравнения на Mac). Размеры — в отчёт.
- Проверь на Mac (whisper.cpp CLI, собранный из того же тега) на 3–4 аятах: что выдаёт модель (с огласовками или без, какие алифы), язык `ar`, нужен ли `initial_prompt`.

### 2. Оценка качества на Mac (главная цифра)

Скрипт `scripts/voice_eval.py` (в репозиторий; данные — в scratchpad):

- **Звук:** поаятные записи 2–3 чтецов, которых мы уже используем (Алафаси и др., тот же источник, что в приложении). Набор: ~100 отрывков по 3–5 аятов, из Джуза Амму и из длинных сур (например, 2, 18, 36, 67). Склейка аятов отрывка в один файл, 16 кГц моно.
- **Распознавание** — whisper.cpp CLI, модель `q8_0` и `q5_0`.
- **Выравнивание** — пословное по нормализованным словам (`WordNormalizer` портирован в скрипт один в один, или вызови Kotlin — как удобнее), результат по каждому слову эталона: верно / пропущено / заменено, плюс лишние слова.
- **Ошибки моделируем на эталоне, а не на звуке:** чтец читает правильно, а эталон портим:
  - «пропуск» — в эталон вставляем слово, которого в звуке нет (берём слово из соседнего аята) → должно найтись «пропущено»;
  - «замена» — слово эталона меняем на похожее (из похожих аятов F6, `similar.tsv`, или из соседнего места) → должно найтись «заменено»;
  - «лишнее» (человек сказал лишнее) — из эталона удаляем слово → «лишнее».
  
  На каждом отрывке — по одной ошибке каждого вида (отдельные прогоны) и прогон без порчи (ложные ошибки).
- **Метрики:** доля найденных пропусков, замен, лишних; ложные ошибки на отрывок (на чистом эталоне); время разбора / длина звука на Mac (для справки). Отдельно — Джуз Амму и длинные суры, отдельно по чтецам.
- **Допуск выравнивания:** подумай, как не считать ошибкой расхождения написания (`ٱلرَّحْمَٰنِ` и т. п.) — нормализация F6 плюс, если нужно, сравнение по скелету с расстоянием ≤ 1 буквы. Опиши, что выбрал.

### 3. Прототип на Android (debug-сборка)

- **Отдельный модуль** `:voiceproto` (Android library, NDK/CMake, JNI к whisper.cpp), подключён **только** как `debugImplementation` в `composeApp`. ABI: `arm64-v8a` (и `x86_64`, если дешево). Release не должен его видеть — проверь merged-манифест и содержимое release APK (`unzip -l`, нет `libwhisper*.so`).
- **Модель на устройстве:** для прототипа — `adb push` в папку приложения (`run-as`, `files/voice/`), либо загрузка по URL из debug-настройки. Хостинга для выпуска нет — это вопрос владельцу, в отчёт.
- **Запись** — `AudioRecord` 16 кГц моно PCM (не AAC из F2a), в память; разрешение RECORD_AUDIO уже есть.
- **Где:**
  - в «Вспомни» (debug) — кнопка «Проверить голосом (прототип)»: читаете отрывок → «Стоп» → разбор → слова отрывка подсвечены: верно (обычный цвет), пропущено, заменено (с тем, что распознано), лишние — списком; плюс время разбора и длина записи;
  - debug-экран «Голос: лаборатория» (вход из debug-меню, если есть, или скрытый): выбрать отрывок, прогнать файл из `files/voice/samples/` (wav), показать результат и время — для замера на реальном телефоне владельцем.
- **Сбор тестовых записей** (для 30 записей тестеров из условий F7): в лаборатории — «Записать образец»: сохраняет wav + json (отрывок, дата) в `files/voice/samples/`, и «Поделиться всеми» (zip через существующий share). Никакой отправки в сеть.
- **Замер на эмуляторе:** время разбора для отрывков 10, 30, 60 с, модели `q5_0` и `q8_0`. Эмулятор — не телефон, цифры только для справки.
- Логику выравнивания положи в commonMain (`common/voice/**`) с тестами — её же использует голосовой поиск в будущем.
